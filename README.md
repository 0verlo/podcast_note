# podcast note

个人学习笔记。收听讲座、对谈类音频节目后，按固定工作流将内容提取为结构化的 Q&A 笔记，保留核心论点与待深挖线索。

## 目录结构

```
├── WORKFLOW.md              # 笔记提取工作流
├── check_note.py            # 审计与上下文准备脚本
├── thresholds.toml          # 审计阈值
├── _concepts/               # 跨笔记概念索引
├── <节目名>/                # 按节目来源分目录
│   ├── raw/                 # 该节目的原始转写文本
│   │   └── 01_xxx.txt
│   └── 01_xxx.md            # 提取后的笔记
```

- 每个节目来源独立一个目录
- `<节目名>/raw/` — 音频转写原文，作为提取的输入素材
- `<节目名>/*.md` — 按 WORKFLOW 提取后的笔记成品，格式为模块化 Q&A + What's Left 线索区

## 设计方法论

WORKFLOW.md 只描述执行时需要知道的设计，设计背后的考虑记录在这里。

### AI 与程序的分工

AI 的产出灵活但不稳定，总结、切分、判断信息密度这类语义工作只能由 AI 完成。程序的产出不灵活但确定，同样的输入必然得到同样的输出。工作流让两者相互制约：AI 负责全部语义判断，程序核对这些判断的可量化后果是否落在约定范围内。

语义一致性没有简单的形式化指标，逐层校验语义只会把审计嵌套下去，带来设计上的过度工程。这里把整套流程建立在一条经验前提上：AI 在几百字的小段落上做总结基本可靠，在数万字的长文本上做总结不可靠。

讲座压缩的难点在于，讲者的信息密度在讲述过程中持续变化。理解讲述逻辑、把内容切成合适的段落、为每一小段判断合适的保留程度并按这个判断执行，是任务的核心。切分位置、档位与最终的重写都由 AI 判断，程序负责确认切分有无疏漏、压缩比是否落在所选档位内。

### 档位代替百分比

早期账本让 AI 为每条 Q 声明一个具体的压缩百分比。实测中这些声明的标准差只有 4–7 个百分点，几乎都落在指引给出的经验带里，而 ±15pp 的执行容差又覆盖了绝大部分合理写法，数字的精度高于它实际承载的判断。把声明改成保留、标准、精简三档后，AI 做的是它更擅长的分类判断，程序核对的是区间。三档的下限取自已有笔记按旧声明分组后的实测 P10，三组之间分得开，说明逐段区分本身是真实的。上限在实测 P90 之上适当放宽：字数本身不敏感，上限主要用来拦截接近转述的写法，过紧时执行者会删掉限定语来凑字数。

档位区间两侧都设门槛。旧流程只把负偏当作错误，引入账本之后的笔记却普遍呈系统性正偏，接近转述。全文层面再用“实际值与档位中值加权期望之差”提示整体偏满或偏简；全文压缩带按材料形式（讲座、对谈、漫谈）分开设定，只作提示，不再强迫 AI 为凑全文均值改动逐条判断。

### 脚本准备上下文

“小段落上可靠”这条前提不仅适用于判断，也适用于读取。由 AI 自己按行号去原文里找内容，会出现读错行、凭记忆写的情况。`pack` 按账本把每条 Q 的原文切片连同行号、语境行、目标字数一起递给 AI，写作和核验都只在这份切片上进行。人工复核时，`show` 用同样的方式把原文与答案并排给出，延续按行号回查原文的习惯。

### 核验复用同一前提

忠实性没有可量化的代理指标，此前完全依赖人工清单。步骤 4 为每条 Q 开一个全新上下文，只给它原文切片和答案，让它列出无依据、归属错误、曲解和关键遗漏，做法参考了 FActScore、QAGS 等以原子事实或问答对照原文的忠实性评估。核验者看不到写作时的推理，绕开了同批生成内容共享注意力状态的问题。

单次核验的召回有限：试运行中对已处置的条目再核验一次，约半数又找出新问题，最常见的是去掉了原文的限定语。所以每条 Q 默认独立核验两次取并集，处置完后再复核一次。复核只做一次，新发现与旧记录去重后追加，链条有明确的终点。

这一步的产出是一份交给人或执行者处置的清单，核验者不改写答案，也不被再审计，所以审计链条在这里同样终止。核验标记以 HTML 注释写在对应 Q 下方，阅读视图中不显示，处置记录在复核期间随笔记保存。

### 定稿清理

正文里的转写错误括注和核验标记服务于写作与核验：括注让回查原文和核验时看得出哪里做了还原，核验标记记录处置过程。人工复核之后，这些信息对阅读不再必要，转写错误已在头部完整登记。所以步骤 7 以“人工反馈解决了全部待核项”为触发条件，由 `strip` 一次性删除核验标记和正文转写错误括注。内容存疑括注保留在正文，因为它提示的是讲者陈述本身的问题，读到该处时就需要知道。

### 指标基底与倒退的终止

切分边界由 AI 自由划定，是流程中最上游的自由度，程序无法从语义上评判一处切分的好坏。坏切分造成的实际危害则集中在可量化的维度：段落过大时压缩判断容易失效，切得过碎时笔记不可读，内容被静默丢弃时细节丢失。边界位置本身的偏差是自限的：错放的内容会落入相邻条目，由那条 Q 自己的覆盖义务和档位兜住。所以一层量化先验就足以约束切分自由，无须更上层的审计。

基底数字取自已有笔记的实测分布，写在 `thresholds.toml`：

| 指标 | 当前值 | 作用 |
|---|---|---|
| Q 密度带 | 600–900 字/Q | 提示切得过碎与漏切 |
| 单 Q 覆盖上限 | 1500 字 | 拦截压缩判断失效的大段落 |
| 档位区间 | 保留 70–95%、标准 55–78%、精简 40–62% | 逐条核对写作是否兑现档位 |
| 整体偏差提示 | 偏离档位中值期望 6pp | 提示系统性转述或系统性丢细节 |
| 保留档占比 | 40% | 提示档位判断整体偏松 |
| 全文压缩带 | 讲座、对谈 55–75%，漫谈 48–70% | 按材料形式提示全文尺度的异常 |

语料增长后可按已提交笔记重新统计，更新由人工触发，不在单次运行中变化。

## Commit 格式

```
<一句话概述>

[Notes]     ← 笔记增删改
[Raw]       ← 原始素材增删
[Chore]     ← 工程及结构相关
[Format]    ← 内容格式/样式调整
```

按需使用相关分类，无变更的分类省略不写。

范例：

```
初始化笔记仓库

[Notes]
1.add 13_语言学相关对谈
2.add 37_相似性与关联

[Raw]
1.add 13_语言学相关对谈
2.add 37_相似性与关联

[Chore]
1.add WORKFLOW.md 笔记提取模板
2.add README.md
```
